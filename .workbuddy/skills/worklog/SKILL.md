# worklog ｜ 任务落账流程

> 本 skill 只回答一件事：**一次任务结束后，日志怎么写、写在哪、写完怎么自查。**
> 不涉及项目架构、端口、启动方式——那些在 `README.md`；硬边界与常用命令在 `Agent.md`。

---

## 0. 调用时机

**在任务收尾阶段调用，不是任务开始时。** 出现以下任一情况即触发：

- 改了代码 / 配置 / 文档 / 数据
- 启动、重启、停止服务，或做了部署
- 跑了测试、验证、故障排查，并得出"通过/失败/修复"结论
- 产出报告、分析结论、方案
- 删除、移动、批量重命名文件

**豁免**：寒暄、释义、单次只读查询、纯格式确认。豁免但产出了会影响后续决策的结论时，仍按需记录。

> 任务进行中不必维护日志草稿；收尾一次性写全即可，避免边做边写。

---

## 1. 四项必填字段（缺一不可）

| 字段 | 写什么 | 合格判定 |
|---|---|---|
| **任务时间** | `YYYY-MM-DD HH:MM → HH:MM`（GMT+8）+ 约耗时 | 取自系统时间，禁止估算或臆造 |
| **任务输入** | 用户原始诉求（可摘要但不改语义）+ 引用的文件/参数/前置状态 | 只看这栏能复现"当时要做什么、在什么基础上" |
| **执行过程** | 关键步骤 + 实际执行的命令 + 技术决策与理由 + 卡点及解决 | 能看出"为什么这么做""卡在哪、怎么通的"，而非流水账 |
| **任务产出** | 新增/修改文件（路径）+ 测试结果 + 结论 + 未完成项 | 有文件必须给路径；声称"通过"必须附证据路径 |

三条例外规则：

1. **不得虚报**：未验证写"未验证"，失败写"失败 + 原因"，部分完成不得写完成。
2. **不得无记录结束**：只要产出了结论或改动，即使一句话的确认也算一个任务。
3. **只追加不改写**：新任务加到当日分区末尾；跨天新建分区并置顶；历史内容仅允许修正错别字和失效链接。

---

## 2. 三级记录，各写各的

| 层级 | 位置 | 写什么 | 不写什么 |
|---|---|---|---|
| **L1 主日志（权威）** | `docs/worklog.md`（项目根目录） | 按第 1 节四项字段的完整任务块；当日概览；问题台账；遗留事项 | 大段技术细节、调试输出 |
| **L2 内部记忆** | `.workbuddy/memory/YYYY-MM-DD.md` | 环境事实、踩坑原文、命令、路径、结论；长期事实写入同目录 `MEMORY.md` | 与 L1 重复的完整叙述 |
| **L3 专项证据** | `tests/evidence/<日期或主题>/` | 测试脚本、结果日志、服务日志、截图 | 结论性文字（放 L1） |

原则：**L1 讲"做了什么、结果如何"；L2 讲"怎么做的、下次注意什么"；L3 是证据。** 三者用路径互相引用，不复制整段。

---

## 3. 任务编号

`T-<YYYYMMDD>-<两位数序号>`，当日递增（`T-20261020-01`、`02`…）。

**同一用户诉求的连续追问并入同一任务块**，在"执行过程"追加一条，不另起编号；只有诉求切换才新增编号。

---

## 4. 写入格式

模板与填好的样例见 `templates/task-block.md`（本 skill 目录下）。

写入位置：`docs/worklog.md` 当日分区（`## YYYY-MM-DD（周X）`）的 `### 任务记录` 小节末尾；该小节不存在则新建。

标题行固定为四级标题：`#### T-20261020-01 ｜ <动词开头的短标题>`。

示例（最小可用版）：

```markdown
#### T-20261020-01 ｜ 修复登录接口 500

- **任务时间**：2026-10-20 10:00 → 10:25（GMT+8，约 25 分钟）
- **任务输入**：用户反馈登录偶发 500；引用 service/auth.py、logs/app.log
- **执行过程**：1) 复现，3/10 失败；2) 定位 token 过期分支未捕获；3) 补 try/except 并加单测
- **任务产出**：`service/auth.py`（修改）；单测 4/4 通过，证据 `tests/evidence/2026-10-20/auth.log`；结论：已修复
```

## 5. 常见错误（写之前先扫一眼）

| 错误 | 表现 | 纠正 |
|---|---|---|
| 记成流水账 | "打开文件、看了一下、又看了另一个" | 只写影响结果的步骤，附命令 |
| 结论无证据 | "测试通过"，没有用例数/日志/截图 | 补 `x/y 通过 + 证据路径` |
| 输入被改写 | 把用户的话"优化"成自己的理解 | 保留原意与关键约束，摘要可，改写不行 |
| 产出只写"已完成" | 说不出改了哪个文件 | 逐个列路径 + 改了什么 |
| 时间造假 | 写整点、写大概 | 取系统时间，写区间 |
| 历史被覆盖 | 直接编辑旧条目 | 追加新块 |

## 6. 落账后自检

```bash
python .workbuddy/skills/worklog/scripts/check_log.py
```

脚本校验：任务块编号格式与唯一性、四项字段是否齐全、时间格式是否合规。全部通过再收尾。

人工再确认三件事：

- [ ] 证据路径真实存在（不是"应该有"）
- [ ] 遗留问题已进问题台账并标级别
- [ ] 环境终态已写（服务是否在跑、端口、临时文件是否清理）
