## 三、执行中遇到的重大问题与修复（重要，务必阅读）

### 问题 1：chromadb 原生层崩溃（进程级 0xC0000005 访问违例）
- **现象**：首次建库时 Python 进程直接崩溃（EXIT=139），定位在 `chromadb_rust_bindings.pyd` 的 `collection.add`；chromadb 1.0.12 与 1.5.9、Ephemeral 与 Persistent 模式均复现。
- **根因**：原生模块导入 `MSVCP140.dll` 的 `_Mtx_lock/_Mtx_unlock`（std::mutex）。该模块由新版 MSVC 工具链编译，而**本机系统运行库为 2022-06 旧版（14.32）**——属已知的"VS2022 17.10+ 编译产物 + 旧运行库 = 互斥锁访问违例"问题。
- **修复（已生效，未改动系统）**：从本机 Edge/WebView2 目录（`C:\Program Files (x86)\Microsoft\EdgeWebView\Application\<版本>\`）提取较新的 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll`，以"应用本地部署"方式放入：
  - `.venv\Scripts\`（python.exe 所在目录）
  - `.venv\Lib\site-packages\chromadb_rust_bindings\`
- **⚠️ 若重建 `.venv`，需重做上述 3 个 DLL 的复制**（或者安装官方最新 VC++ 2015-2022 运行库一劳永逸：`https://aka.ms/vs/17/release/vc_redist.x64.exe`，安装需管理员权限；本次按用户决定未执行系统安装）。

### 问题 2：残留/半成品向量库目录触发 Rust panic
- **现象**：崩溃中断后遗留的 `db_md/`、`db_test_*` 目录再次运行时报 `pyo3_runtime.PanicException: range start index 10 out of range for slice of length 9`（社区 issue #5909 同类，分段实验确认）。
- **修复**：删除残留目录重建即可；日常规范——**崩溃/中断后先清理 `db_md` 再重跑**；换知识或换 Embedding 模型用 `REBUILD_VECTORSTORE=True` 重建一次。

### 问题 3：偶发结构化输出解析失败（已加固）
- **现象**：一次请求中间歇报 `RAG 请求错误：400`（服务端日志显示某次文档评分调用后中断）。复现实验证明为**偶发**（同问题二次执行即成功）。
- **根因**：混元偶发返回非严格 JSON，langchain 结构化解析抛 `OutputParserException`（属 ValueError 家族），被 `server.py` 的 `ValueError→400` 映射暴露。
- **修复**：`_structured()` 增加 `with_retry(stop_after_attempt=3)` 自动重试（见第一节"附加加固"）；重启服务后联调通过。

## 四、已知问题与限制（不阻塞，供参考）

1. **Pydantic serializer warnings**（`Expected 'none' - serialized value may not be as expected`）：langchain 结构化输出与 pydantic 序列化的兼容性提示，**无害**，大量出现在日志中，演示时可用 `-W ignore` 或忽略。
2. `@app.on_event("startup")` 弃用警告：FastAPI 0.115/0.143 均提示，可改为 lifespan（可选优化）。
3. `langchain_community.vectorstores.Chroma` 弃用提示：建议后续迁移 `langchain-chroma` 包（可选）。
4. `nodes.py` 的熔断计数器为**类级共享**，多会话并发提问可能相互影响（教学版已知取舍，单用户无碍）。
5. `requirements.txt` 未锁定版本：本机实测组合为 chromadb 1.5.9 / langchain 0.3.30 / langgraph 1.0.1 / fastapi 0.115.9；如换环境出现兼容问题，可参考本记录锁定。
