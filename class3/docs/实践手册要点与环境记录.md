# LangGraphRAG 项目环境与教学实践要点记录

> 文档用途：记录本项目跑通所需环境/软件，明确 **LangGraph + RAG** 架构定位（是否多智能体、职责边界），并提炼可供学生实践手册采用的核心能力点。  
> 基于仓库当前实现整理（**混元 TokenHub 对话** + **TokenHub Embedding（国内站）** + Chroma + FastAPI 端口 `14052`）。

---

## 1. 需要配置的环境与软件

### 1.1 本机基础环境

| 类别 | 要求 | 说明 |
|------|------|------|
| 操作系统 | Windows 10/11（或其他可跑 Python 的系统） | 本课程环境以 Windows 为例 |
| Python | **3.12**（推荐） | 用 `uv` 或官方安装包均可 |
| 虚拟环境 | 项目目录下 `.venv` | 隔离依赖，避免污染系统 Python |
| 包管理 | `pip` 或 `uv` | 安装 `requirements.txt` |
| 网络 | 可访问 TokenHub（混元对话 + Embedding） | 建库与问答均依赖云端接口 |
| Git（可选） | 任意较新版本 | 便于提交实验代码 |

**不必需：** Docker、GPU、Milvus、本机部署大模型（当前方案为云端 API）。

### 1.2 必装 Python 依赖（概要）

以 `requirements.txt` 为准，核心包括：

| 包 | 作用 |
|----|------|
| `langgraph` | 状态图编排（路由、循环、条件边） |
| `langchain` / `langchain-core` / `langchain-community` / `langchain-openai` | LLM 调用、提示词链、向量库对接 |
| `chromadb` | 本地向量库持久化 |
| `python-dotenv` | 读取 `.env` |
| `fastapi` + `uvicorn` | HTTP 接口（端口 14052）；对话 UI 由实训三提供 |
| `pydantic` | 结构化输出 schema |
| `openai` / `tiktoken` | OpenAI 兼容客户端传递依赖（TokenHub 对话 / Embedding 均走兼容协议） |

安装示例：

```powershell
cd 项目根目录
uv venv --python 3.12 .venv
uv pip install -r requirements.txt --python .venv\Scripts\python.exe
```

### 1.3 云服务账号与密钥（当前配置方案）

本项目将 **对话模型** 与 **向量化模型** 拆开配置：

| 用途 | 厂商 / 服务 | 配置项 | 模型示例 |
|------|-------------|--------|----------|
| 路由、打分、生成、改写 | 腾讯混元 TokenHub | `HUNYUAN_API_KEY`、`OPENAI_API_BASE`、`LLM_MODEL` | `hy3` |
| Embedding 建库与检索 | 腾讯 TokenHub（国内站） | `EMBEDDING_API_BASE`、`EMBEDDING_MODEL`（Key 可复用 HUNYUAN_*） | `kinfra-text-embedding-0.6b`（1024 维） |

`.env` 关键配置（密钥勿提交仓库；完整字段见 `.env.example`）：

```env
# LLM（混元 TokenHub）
HUNYUAN_API_KEY=你的TokenHub密钥
OPENAI_API_BASE=https://tokenhub-intl.tencentmaas.com/v1
LLM_MODEL=hy3

# Embedding（TokenHub 国内站，Key 可与上共用）
EMBEDDING_API_BASE=https://tokenhub.tencentmaas.com/v1
EMBEDDING_MODEL=kinfra-text-embedding-0.6b
EMBEDDING_BATCH_SIZE=64

# 数据与向量库
DATA_DIR=./data/md
PERSISTANT_STORAGE_DIR=./db_md
REBUILD_VECTORSTORE=False

# Web 服务
API_HOST=0.0.0.0
API_PORT=14052
```

**兼容性注意：**

- Key 也可填 `OPENAI_API_KEY` / `TOKENHUB_API_KEY`（优先读 `HUNYUAN_API_KEY`），便于与实训二共用。
- Embedding 也可单独设 `EMBEDDING_API_KEY`；未设时复用对话 Key。
- 混元结构化输出默认自动用 **`json_schema`**（可用 `LLM_STRUCTURED_METHOD` 显式指定）。
- 换 Embedding 模型后必须 `REBUILD_VECTORSTORE=True` 重建向量库。

### 1.4 数据与产物目录

| 路径 | 说明 |
|------|------|
| `data/md/**/*.md` | **进向量库的知识文件**（由 `DATA_DIR` 指定）；当前为 30 篇腾讯产品代表性文档 |
| `db_md/` | Chroma 持久化向量库（换知识后需 `REBUILD_VECTORSTORE=True` 重建一次） |
| `.env` | 本地密钥与运行参数（应在 `.gitignore` 中） |

### 1.5 启动方式

**网页 + 接口（推荐）：**

```powershell
.\.venv\Scripts\python.exe server.py
```

- 健康检查：`GET /health`  
- 服务说明：`GET /`（JSON）  
- 聊天接口：`POST /chat`  
- 对话 UI：实训三「RAG 模式」→ `http://127.0.0.1:14052`  

**终端模式：**

```powershell

```

输入问题回车；输入文字 `exit` 后回车退出（不是某个特殊按键）。

## 2. 架构定位：LangGraph + RAG，是否多智能体？

### 2.1 一句话结论

| 问题 | 结论 |
|------|------|
| 是不是 LangGraph + RAG？ | **是** |
| 是不是多智能体（Multi-Agent）？ | **不是典型多智能体**；是 **单 Agent（单图）+ 多节点工作流** |
| 更准确的教学称谓 | **自适应 / 纠正式 RAG（Adaptive / Corrective RAG）**，用 LangGraph 做状态机编排 |

### 2.2 为什么不是多智能体？

多智能体通常具备：

- 多个相对独立的 Agent（各自目标、记忆、工具）
- Agent 之间消息传递、协商或分工协作
- 常有 supervisor / 并行子代理 等组织方式

本项目实际是：

- **一张** `StateGraph`，共享同一份状态：`question` / `documents` / `generation` / `message_history`
- 「路由、改写、检索、打分、生成」是图上的 **节点（Node）**，不是多个可独立运行的 Agent
- 决策通过 **条件边（conditional edges）** 完成，而不是 Agent 间对话

因此：教学上可称「多角色能力模块」，但不宜写成「多智能体系统」以免概念混淆。

### 2.3 流程图（逻辑）

```text
用户问题
   │
   ▼
[路由 route_question]
   ├─ casual_convo ──► [generate] ──► END
   └─ vectorstore  ──► [transform_query] ──► [retrieve]
                              ▲                  │
                              │                  ▼
                              │         [grade_documents]
                              │            │         │
                              └────────────┘         │（有相关文档）
                         （无相关且未超重试）         ▼
                                              [generate]
                                                 │
                         ┌───────────────────────┼───────────────────────┐
                         │ not supported         │ useful                │ not useful
                         ▼                       ▼                       ▼
                    再 generate                 END              transform_query
```

### 2.4 「角色 / 节点」职责边界（教学可用）

虽非多智能体，但可按职责边界拆解，方便实验分工：

| 名称（教学可称「角色模块」） | 代码位置 | 职责边界（做什么） | 不负责（边界外） |
|------------------------------|----------|--------------------|------------------|
| 路由器 Router | `models.Router` + `nodes.route_question` | 判断闲聊 vs 知识问答 | 不检索、不最终长文生成（闲聊路径会复用 generate） |
| 查询改写器 QuestionRewriter | `models.QuestionRewriter` + `nodes.transform_query` | 结合历史，优化检索问句 | 不直接回答用户 |
| 检索器 Retriever | `loader` + `nodes.retrieve` | 向量相似度取文档块 | 不判断相关性、不生成答案 |
| 文档评分器 DocGrader | `models.DocGrader` + `nodes.grade_documents` | 过滤与问题无关的检索结果 | 不改写问题、不生成答案 |
| 生成器 Generator | `models.Generator` + `nodes.generate` | 基于 context + history 生成回答 | 不负责自我判定是否幻觉（由后续评分） |
| 幻觉评分器 HallucinationGrader | `models.HallucinationGrader` | 判断生成是否 grounded | 不重新检索 |
| 答案评分器 AnswerGrader | `models.AnswerGrader` | 判断是否真正回答了问题 | 不负责向量检索 |
| 图编排 Graph | `modules/graph.py` | 定义节点连线、循环与终止 | 不含业务 prompt 细节 |
| 知识入库 Loader | `modules/loader.py` | 读 `data/md`、切块、Embedding、Chroma | 不含问答对话逻辑 |
| Web 服务 | `server.py` | HTTP API 与会话 id；不含 RAG 核心决策（调用 `rag_app.ask`）；UI 由实训三提供 |

**熔断参数（防死循环）：**

- `REGENERATION_THRESHOLD`：生成重试上限（默认 5）  
- `RERETREVIAL_THRESHOLD`：重检索/改写上限（默认 3）  

### 2.5 与「真多智能体」对照（给学生辨析）

| 维度 | 本项目 | 真多智能体示例 |
|------|--------|----------------|
| 组织方式 | 单图多节点 | 多 Agent + 通信 |
| 状态 | 共享 `GraphState` | 常各有 memory / 工具集 |
| 协作 | 条件边自动流转 | 显式委派、辩论、投票等 |
| 扩展方向 | 可演进为「检索 Agent + 写作 Agent」 | 从一开始就按 Agent 设计 |

## 3. 可提取到《实践手册》的核心内容（供学生完成）

以下按「必做 / 选做 / 拓展」分层，便于写成实验任务。

### 3.1 必做实验（建议写入手册主线）

| 序号 | 实践主题 | 学生要完成什么 | 对应模块 / 验收点 |
|------|----------|----------------|-------------------|
| P1 | 环境与配置 | 创建虚拟环境、填写 `.env`、启动服务 | `GET /health` 返回 ok，或终端 `main.py` 可问答 |
| P2 | 知识入库 | 检查 `data/md` 中的腾讯产品 Markdown；更换资料后用 `REBUILD_VECTORSTORE=True` 重建一次 | 对新内容提问能命中（如询问云服务器密码重置） |
| P3 | 朴素 RAG 链路 | 实现或梳理「检索 → 拼接 prompt → 生成」最小闭环 | 能对照代码画出数据流 |
| P4 | LangGraph 状态与边 | 阅读 `GraphState`、节点与条件边；画本项目状态图 | 提交流程图 + 简要说明 |
| P5 | 路由设计 | 修改 Router 的 system prompt，区分闲聊 vs 客服知识问题 | 用样例验证：如「今天天气？」→闲聊；「企业微信如何获取 access_token？」→向量库 |
| P6 | 查询改写 | 观察多轮追问下接口/日志中的 `rewritten_question`（或调试打印） | 说明改写如何利用 `message_history`（如先问腾讯会议如何入会，再问「移动端呢」） |
| P7 | 文档相关性过滤 | 理解 DocGrader；对比易混产品场景 | 记录过滤前后文档来源差异 |
| P8 | 生成后校验 | 理解幻觉评分与答案评分；理解阈值熔断 | 回答「为何需要校验与阈值」；说明不可编造功能、权限、版本或时效 |

### 3.2 选做实验（手册进阶章节）

| 序号 | 实践主题 | 学生要完成什么 |
|------|----------|----------------|
| S1 | Embedding 供应商切换 | 在保持 Chroma 的前提下更换 Embedding 模型，并重建库 |
| S2 | LLM 供应商切换 | 更换对话模型（如换混元其他型号）；处理 `json_schema` vs `function_calling` 兼容问题 |
| S3 | 切块策略 | 调整 `chunk_size` / `chunk_overlap`，对比检索质量 |
| S4 | API 封装 | 调用 `POST /chat`，用 curl/Postman 完成多轮 `session_id` 问答 |
| S5 | 前端体验 | 对接实训三 RAG 模式；观察 sources / steps |

### 3.3 拓展实验（挑战题 / 课程设计）

| 序号 | 实践主题 | 说明 |
|------|----------|------|
| E1 | 引入 Rerank | 在 retrieve 后增加重排序节点 |
| E2 | 真·多智能体改造 | 将「检索」与「写作」拆成两个 Agent，经 Supervisor 协作 |
| E3 | 可观测性 | 记录每步耗时、token、节点路径，做简单调试面板 |

### 3.4 建议写入手册的「知识要点清单」

1. **RAG 三件套：** 索引（切块+Embedding）→ 检索 → 增强生成。  
2. **为何要 LangGraph：** 分支、循环、校验，而不是单次 retrieve。  
3. **状态机思维：** 共享状态字段如何在节点间传递。  
4. **结构化输出兼容：** `json_object` / `json_schema` / `function_calling` 差异（混元侧优先 `json_schema`）。  
5. **对话与向量可同源：** LLM 与 Embedding 均可走 TokenHub（国内站 Embedding + 可选国际站对话）。  
6. **工程约束：** 换 Embedding 必须重建向量库；会话与端口暴露。

### 3.5 建议的学生交付物模板

- 环境配置截图或检查清单（脱敏，勿交 API Key）  
- 一张 LangGraph 流程图（自绘）  
- 路由 / 改写 / 过滤 各至少 2 组对比样例（建议覆盖不同腾讯产品）  
- 简短实验报告（问题、改动、结果、反思）  
- （选做）`POST /chat` 调用记录或实训三 RAG 对接说明  

**样例问答（可用于验收与报告）：**

1. 企业微信如何获取 `access_token`？  
2. 腾讯会议如何通过会议号加入会议？  
3. 腾讯云服务器如何重置实例密码？
