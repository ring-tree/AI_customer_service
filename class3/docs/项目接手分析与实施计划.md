## 一、现状结论（一句话）

本项目是**实训四"学生挖空版"**：骨架、节点逻辑、知识库、文档均已就绪，但 **7 处 `TODO(学生)` 尚未实现**，且**运行环境尚未初始化**（无 `.env`、无 `.venv`、无 `db_md` 向量库）。当前代码**无法直接启动**——`get_graph()` 链路会在 `TODO-4 → TODO-5 → TODO-6` 上依次抛 `NotImplementedError` / `501`。

即：**下一步的核心工作 = 补齐 7 处缺口 + 初始化环境 + 建库 + 联调验收**。

## 三、关键发现与风险点（实施前必读）

| # | 发现 | 影响 | 处置 |
|---|------|------|------|
| 1 | `.env` 不存在（仅 `.env.example`） | 服务启动即被 `validate_env()` 拦截退出 | 阶段一创建并填写 |
| 2 | `.env.example` 对话默认 `OPENAI_API_BASE` 为**国际站**（tokenhub-intl） | 实训二 Key 属**中国站**，地域不匹配会 401 | `.env` 中改为中国站 `https://tokenhub.tencentmaas.com/v1` |
| 3 | `REBUILD_VECTORSTORE=False` 为默认，且 `db_md` 不存在 | 首次运行若未置 True 会走建库分支（TODO-2 未实现会直接报错）；建成后应改回 False | 首次建库前置 `True` |
| 4 | 本机 Python：managed 3.13.14（pip 26.1.2）/ 系统 3.11.1；**无 3.12、无 uv** | 文档推荐 3.12，需降级适配 | 优先用 3.13 建 venv；若依赖有兼容问题回退 3.11（或补装 3.12） |
| 5 | 未配置 pip 镜像，PyPI 直连可能慢 | 依赖安装（chromadb/langchain 体量较大）耗时长 | 可加 `-i` 国内镜像加速；安装放后台执行 |
| 6 | `nodes.py` 的 `REGENERATION_COUNT/RERETREVIAL_COUNT` 为**类级共享**计数器 | 多会话并发时计数互相影响（教学版已知取舍） | 不改动，联调时单会话验证；记录为已知限制 |
| 7 | `server.py` 使用 `@app.on_event("startup")` | 新版 FastAPI 会提示 deprecation 告警 | 运行验证时观察，如告警不改（非错误）；可留作优化项 |
| 8 | 架构图 `vectordb_creation.png` 仍标注旧方案（pdfkit / text-embedding-ada-002 / chunk 1000） | 与现行代码（纯 md / kinfra-embedding / 建议 800+120）不一致 | 以代码与 `docs/实践手册要点与环境记录.md` 为准；可选更新图 |

## 四、下一步实施计划（步骤 / 目标 / 涉及文件 / 执行顺序）

> 执行总顺序：**阶段一（环境）→ 阶段二（补代码）→ 阶段三（建库+本地验收）→ 阶段四（与实训三联调）→ 阶段五（记录收尾）**
> 阶段一与阶段二可部分并行：依赖安装放后台执行的同时，先写 `.env`、再做冒烟验证、随后进入编码。

### 阶段一：环境与配置（不动业务代码）

**S1. 创建虚拟环境并安装依赖**
- 目标：得到可运行的 `.venv`（隔离环境），满足 `requirements.txt`。
- 涉及文件：`requirements.txt` → 生成 `class3/.venv/`
- 操作（按序）：
  1. `python -m venv .venv`（用 managed 3.13）；
  2. `.venv\Scripts\python.exe -m pip install -r requirements.txt`（建议加国内镜像参数；**后台执行**，视网络 5~15 分钟）；
  3. 安装完成后校验：`python -c "import langgraph, langchain, chromadb, fastapi; print('deps ok')"`。
- 验收：6 个核心包全部可 import；无版本冲突报错。
- 回退：若 3.13 出现 wheel 兼容问题 → 改用系统 3.11 重建 venv。

**S2. 创建并填写 `.env`**
- 目标：密钥、基址、端口、建库开关全部就位。
- 涉及文件：新建 `class3/.env`（从 `.env.example` 复制）
- 关键字段（按序确认）：
  - `HUNYUAN_API_KEY` = 复用实训二 `class1/02api-proxy/.env` 中的 TokenHub Key；
  - `OPENAI_API_BASE=https://tokenhub.tencentmaas.com/v1`（**改掉模板里的国际站**，与 Key 地域一致）；
  - `LLM_MODEL=hy3`；
  - `EMBEDDING_API_KEY` = 同上复用；`EMBEDDING_API_BASE=https://tokenhub.tencentmaas.com/v1`；`EMBEDDING_MODEL=kinfra-text-embedding-0.6b`；
  - `REBUILD_VECTORSTORE=True`（**仅为首次建库**，S10 后改回 False）；
  - `API_PORT=14052`、`API_HOST=0.0.0.0`；`REGENERATION_THRESHOLD=5`、`RERETREVIAL_THRESHOLD=3`。
- 验收：`python -c "from modules.env_utils import ..."` 式的 Key 校验通过（`validate_env()` 不退出）。

**S3. 上游接口冒烟验证（写代码前做，避免白干）**
- 目标：确认"对话"与"Embedding"两个上游接口用本 Key 均可用。
- 涉及文件：无（用 curl / Python stdlib 直连）
- 操作：分别请求 `POST {base}/chat/completions`（hy3，一句短问）与 `POST {base}/embeddings`（kinfra-text-embedding-0.6b，单条文本）。
- 验收：对话返回 200 且有 content；Embedding 返回 200 且向量维度 = **1024**（TokenHub kinfra 固定维度）。

### 阶段二：补齐 7 处代码缺口（核心工作，按依赖序）

> 顺序不可乱：`loader(1,2) → models(3a,3b) → graph(4) → rag_app(5) → server(6)`，后者的运行都依赖前者的产物。

**S4. `modules/loader.py` → TODO-1：`build_embeddings()`**
- 目标：构造 OpenAI 兼容 Embedding 客户端（TokenHub 国内站）。
- 要点：Key 用 `read_env_value("EMBEDDING_API_KEY","HUNYUAN_API_KEY",...)`；`base_url` 取 `EMBEDDING_API_BASE` 并去尾斜杠（**不要带 /embeddings**）；`model=EMBEDDING_MODEL`；`check_embedding_ctx_length=False`；`model_kwargs={"encoding_format":"float"}`（TokenHub 不支持 base64）。
- 验收：单独调用 `build_embeddings().embed_query("测试")` 返回 1024 维向量。

**S5. `modules/loader.py` → TODO-2：建库流程**
- 目标：`data/md/**/*.md` → 切块 → 向量化 → Chroma 持久化到 `db_md/`。
- 要点：`DirectoryLoader`（`glob="**/*.md"`，`TextLoader` + UTF-8，`silent_errors` 视情况）；`RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=120)`；过滤空 chunk；`Chroma.from_documents(..., persist_directory=...)`（当前 langchain 版本自动持久化）。
- 验收：`db_md/` 生成且非空；重复调用走"加载已有库"分支不重建。

**S6. `modules/models.py` → TODO-3a/3b：客服 Prompt**
- 目标：Router 与 Generator 两个 system prompt 落地为客服语境。
- 要点：
  - 3a（Router）：知识相关（企业微信/腾讯会议/腾讯云服务器/腾讯云对象存储/微信小程序/客服规则）→ `vectorstore`；纯寒暄、闲聊、与上述无关 → `casual_convo`；
  - 3b（Generator）：只依据检索资料与对话历史回答；不编造资费/功能/权限；不确定或超出知识库时提示转人工。
- 验收：S11 中用两类样例分别命中不同路由；回答中不出现编造内容。

**S7. `modules/graph.py` → TODO-4：拓扑连线**
- 目标：按第三节流程图把 5 个节点连成自适应 RAG 图并 `compile()`。
- 要点（连通关系，条件映射名与 `nodes.py` 返回值一致）：
  - `set_conditional_entry_point(route_question)` → `casual_convo` | `vectorstore`；
  - `add_edge(generate_conv_reply → END)`；`transform_query → retrieve → grade_documents`；
  - `add_conditional_edges(grade_documents, decide_to_generate)` → `transform_query` | `generate`；
  - `add_conditional_edges(generate, grade_generation_v_documents_and_question)` → `not supported→generate` / `useful→END` / `not useful→transform_query`。
- 验收：`get_graph()` 能 `compile()` 成功；`DEBUG=True` 时终端可见节点流转日志。

**S8. `modules/rag_app.py` → TODO-5：`ask()`**
- 目标：跑一轮 `graph.stream`，产出 web_ui 契约所需的 `{answer, message_history, sources, steps}`。
- 要点：`inputs={question, message_history, documents:[]}`；流式收集节点名（steps）与最新 `documents`/`generation`；**沿用 nodes 的消息编号格式**把回答追加进 `message_history`；sources 从 `documents` 提取 `{source, metadata, preview}`。
- 验收：`main.py` 可正常一问一答且返回 sources。

**S9. `server.py` → TODO-6：`POST /chat`**
- 目标：会话化的 HTTP 问答接口（实训三联调的直接对象）。
- 要点：`session_id` 空则 `uuid4()`；从 `_sessions` 取/建 history；`ask()` 后写回；返回 `ChatResponse(session_id, answer, sources, steps)`；`ValueError→400`，其它异常→`500`。
- 验收：S12 的接口用例全过。

### 阶段三：建库与本地验收（端到端）

**S10. 首次构建向量库**
- 目标：生成 `db_md/`。
- 操作（按序）：确认 `.env` 中 `REBUILD_VECTORSTORE=True` → 启动 `server.py`（首次会打印 `Building vectorstore...`，30 篇文档量小，预计分钟级）→ 观察 `RAG graph ready.` → **将 `REBUILD_VECTORSTORE` 改回 `False`**（否则每次启动都重建、费时费钱）。
- 验收：`db_md/` 非空；日志显示建库完成且服务开始监听 14052。

**S11. 终端链路验收（main.py）**
- 目标：不经过 HTTP 验证图 + 检索 + 生成全链。
- 操作：`.venv\Scripts\python.exe main.py`，依次用 6 个推荐问法（企业微信 access_token / 腾讯会议入会 / CVM 重置密码 / COS 建桶 / 小程序凭证 / 转人工），另加 1 个闲聊问句（如"今天天气怎么样"）验证 `casual_convo` 分支。
- 验收：知识问题有据可答；闲聊走 `generate_conv_reply`；至少记录 1 组"多轮指代"样例（先问入会、再问"移动端呢"）看改写效果。

**S12. HTTP 接口验收（server.py）**
- 目标：验证实训三联调所需的全部接口与契约。
- 用例（按序）：`GET /health`、`GET /` → `POST /chat`（单轮）→ `POST /chat`（带上次 `session_id` 追问）→ `POST /chat/reset` 后再问（应失忆）→ 异常用例（空 `question` 应有 422/400）。
- 验收：响应结构含 `session_id/answer/sources/steps`；多轮生效；reset 生效。

### 阶段四：与实训三（web_ui）端到端联调

**S13. RAG 模式全链联调**
- 目标：验证"企业智能客服"前端 RAG 模式与本服务完整打通（这也是实训四 S5 验收项）。
- 涉及文件：`class2/web_ui`（启动 dev 服务）；无需改本仓库代码。
- 操作（按序）：① 启动 class3 `server.py`（:14052）；② 启动 web_ui `npm run dev`（:3098）；③ 设置面板切「实训四 RAG」→ 测试连接；④ 发送知识问题与闲聊问题各一；⑤ 检查回答下钻的「引用来源 / 推理步骤」面板、RAG 徽标、加载文案"知识检索中..."。
