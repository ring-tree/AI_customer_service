### A. class1/02api-proxy（模型网关，:11434）

#### A1 ｜ 教学 TODO 注释大面积残留（P3）
- **位置**：`src/index.js` 全文件 **37 处**，代表行：L32（Provider 注册）、L44/56/66/76（四厂商）、L92/104（模型别名与回退表）、L208（分流开关）、L309（非流式）、L355/378（SSE）、L460/466/471（流式入口）、L503/511（chat 总处理器）、L573（模型列表）
- **现象**：注释写着 `TODO(学生)-n：补全本函数`，其下方代码已完整实现（`handleOpenAIChatCompletions` L511 后即为完整逻辑）
- **影响**：① 评审误判为未完成；② 后续 Agent/开发者可能重复实现或误删已实现代码；③ 与 `README.md`「学生版，请完成 TODO」的口吻叠加，导致交付状态失真
- **建议**：批量改写为 `// [手册 TODO-n] 已实现`，保留可追溯性；或加文件头统一声明「本文件为完整版，TODO 注释仅作手册对照」。约 30 分钟机械替换，零逻辑风险

#### A2 ｜ 未透传 `response_format` / `tools` / `tool_choice`（P1）
- **位置**：`src/index.js` L511（`handleOpenAIChatCompletions` 请求解构）、L238（`buildOpenAIChatBody` 组包）
- **现象**：请求侧只取 `model/messages/stream/temperature/top_p/max_tokens/stream_options`；全文件 grep `response_format|tools|tool_choice` **0 命中**
- **影响**：① class3 的路由/评分链依赖 `json_schema` 结构化输出，若经本网关调用会静默降级为自由文本，解析大概率失败；② 外部 OpenAI 客户端使用 function calling 直接不可用。这是「网关收敛（L2）」的硬前置
- **建议**：解构补 3 个字段并在 `buildOpenAIChatBody` 原样透传（约 10 行）；补一条回归用例：带 `response_format: {type:'json_schema'}` 请求，断言上游收到该字段

#### A3 ｜ 缺 `/v1/embeddings` 路由（P1）
- **位置**：`src/index.js` L563-582 路由表（仅 `/`、`/health`、`/v1/models`、`/v1/chat/completions`）
- **影响**：向量化无法收敛到网关，class3 必须自持第二把密钥；与「A1 一把密钥」的定位冲突
- **建议**：新增 `POST /v1/embeddings` 透传（复用 fetch 分支，约 20 行），并在 `/v1/models` 中按需暴露 embedding 模型；class3 `.env` 的 `EMBEDDING_API_BASE` 可切到 `http://localhost:11434/v1`

#### A4 ｜ 流式收尾重复 `finish_reason:"stop"` 帧（P2）
- **位置**：`src/index.js` L442（`streamOpenAICompatibleFetch` 收尾无条件 `writeOpenAISSE(..., 'stop')`）
- **现象**：上游 finish 帧已透传，收尾再补一条 → 实测 `finish_frames=2 ['stop','stop']`
- **影响**：对以 `[DONE]` 为准的客户端无实际危害；严格按 finish 计数的 SDK 可能重复触发回调
- **建议**：循环内记录 `finishForwarded`，收尾仅在未发送时补帧；补一条流式帧序断言用例

#### A5 ｜ `charset` 写成独立响应头（P3）
- **位置**：`src/index.js` L155（`sendJSON` 的 headers）
- **影响**：`charset: utf-8` 并非标准头，个别代理/客户端可能忽略；实测中文无乱码
- **建议**：合并为 `'Content-Type': 'application/json; charset=utf-8'`

#### A6 ｜ 无鉴权、CORS 全开、无 `/v1/models/{id}`（P3）
- **位置**：`src/index.js` L563（路由表）、L594（`createServer`）、CORS 头 L~150
- **影响**：任何能访问 11434 的进程都可消耗 TokenHub 额度；缺少模型详情端点，部分 SDK 的 `models.retrieve` 不可用
- **建议**：教学场景在 README 明确「仅本机」；如需外露，加 `PROXY_TOKEN` 校验（Bearer 比对）。模型详情端点可按需补，优先级低

#### A7 ｜ 3 个 Provider 未配置 Key（P3）
- **位置**：`.env`（仅 `HUNYUAN_API_KEY`；deepseek/zhipu/kimi 全被注释）、`models.json`（含 4 个对应别名）
- **影响**：`/v1/models` 已按 Key 过滤，不会报错；但用户会疑惑「为什么只有 3 个模型」
- **建议**：README 的模型清单标注「仅列出已配置 Key 的厂商」；或在 `models.json` 只保留混元别名

#### A8 ｜ 请求体无大小上限（P3）
- **位置**：`src/index.js` L594 起的 `createServer` 与 `getBody`
- **影响**：超大 body 全量读入内存，单机演示影响有限

### B. class2/web_ui（客服工作台，:3098）

#### B1 ｜ 附件/图片「只展示、不上传」——功能假象（P1）
- **位置**：`src/components/ChatInput.tsx` L103（`accept=".pdf,.doc,.docx,.txt"`）、L114（`accept="image/*"`）、L22（`onSend({text, files})`）；`src/views/HomePage.tsx` L194-236（`handleSend`）；`src/components/ChatMessage.tsx` L148-150（渲染）
- **现象**：文件被读成 `FileItem` 放进消息并渲染成卡片，但 `handleSend` 组装历史时只映射 `{role, content}`，**从未把文件内容送进 prompt**；RAG 分支连 `files` 都不传
- **影响**：用户以为上传生效、模型完全看不到内容——最典型的「半成品功能」。若演示「上传合同问答」会直接穿帮
- **建议**（二选一）：
  - **实现**：文本类走 `FileReader.readAsText` → 截断（如 8k 字）拼进 user message；图片走视觉模型（`hy-vision-*`）或先 OCR；
  - **收敛**：暂时隐藏附件入口或置灰并标注「暂不支持」，避免假象（1 小时可完成，推荐先做这个）

#### B2 ｜ `npm run lint` 不可用（P3）

- **影响**：静态门禁失效，`devDependencies` 里的 eslint 相关包成为死重量
- **建议**：补 `.eslintrc.cjs`（ESLint 8 legacy：`@typescript-eslint/parser` + `react-hooks` + `react-refresh`，`parserOptions.project: tsconfig.json`），或直接删除 lint 脚本与依赖

#### B3 ｜ TODO 注释残留（P3）

#### B4 ｜ 所有 fetch 均无超时/取消（P2）

- **建议**：统一封装 `fetchWithTimeout(url, opt, ms)`；对话 60s、RAG 180s；配合 `AbortController` 在「重新生成/停止」时中断

### C. class3（RAG 知识服务，:14052）

#### C1 ｜ Key 校验的「友好提示」实际不可达（P2｜静态推断）
- **位置**：`modules/models.py` L35（模块导入时即执行 `validate_llm_api_key(LLM_API_KEY)`）；`modules/rag_app.py` L7（import models 在前）、L70（`validate_env()` 在后）
- **现象**：缺 Key/占位 Key 时，`import models` 直接抛 `ValueError`，早于 `rag_app.validate_env()` 打印中文指引
- **影响**：新环境首次启动看到的是 traceback，而非「请编辑 .env …」的明确提示，排障成本上升
- **建议**：把 `validate_llm_api_key` 从模块级移到 `get_graph()` 内（或 `ChatOpenAI` 构造前），让 `validate_env()` 的提示路径真正生效

#### C2 ｜ 熔断阈值无默认值（P2）
- **位置**：`modules/nodes.py` L14-15：`int(os.getenv("REGENERATION_THRESHOLD"))`、`int(os.getenv("RERETREVIAL_THRESHOLD"))`
- **影响**：`.env` 缺这两项时 `int(None)` 抛 `TypeError`，服务启动即失败（换环境/精简配置时高发）
- **建议**：`int(os.getenv("REGENERATION_THRESHOLD", "5"))`，与 `loader.py` 的写法保持一致

#### C3 ｜ `.env.example` 与代码默认基址指向国际站（P2）
- **位置**：`.env.example` L8（`OPENAI_API_BASE=https://tokenhub-intl.tencentmaas.com/v1`）；`modules/models.py` L22（`DEFAULT_LLM_API_BASE` 同为 intl）
- **影响**：课程 Key 属中国站，照抄 example 会稳定 401/401002——这正是协同分析里 C2 项标记的坑，尚未修
- **建议**：两处均改为中国站并加注释「密钥与地域必须一致」

#### C4 ｜ 纯空白问题触发 4 轮检索环（P2）
- **位置**：`server.py` L29（`question: str = Field(..., min_length=1)`）+ L67-96（`/chat`）
- **现象**：`"   "` 可通过 `min_length=1` 校验；实测 134s、`steps` 出现 4 组 `transform_query→retrieve→grade_documents`、`sources=0`
- **影响**：白烧 4 轮检索与评分调用（约 8~12 次模型调用），响应极慢
- **建议**：`/chat` 入口加 `if not req.question.strip(): raise HTTPException(400, "question 不能为空")`；顺带加 `max_length=2000`

#### C5 ｜ `_sessions` 无上限、无 TTL（P3）
- **位置**：`server.py` L25（`_sessions: dict[str, list] = {}`）、L89（`_sessions[session_id] = result["message_history"]`）
- **影响**：每个新会话常驻全量历史，长跑/多人使用内存单调增长，且无回收
- **建议**：`OrderedDict` + LRU（如 200 会话）或按最后访问时间 TTL 回收；生产化再考虑 Redis

#### C6 ｜ 熔断计数为类级共享（P2）
- **位置**：`modules/nodes.py` L16-17（`REGENERATION_COUNT = 0` / `RERETREVIAL_COUNT = 0` 为类属性）、L163-164（`route_question` 重置）
- **影响**：单进程多会话并发时互相清零/累加，可能出现「A 会话把 B 会话的重试预算吃掉」
- **建议**：改为按 `session_id` 计数的字典，或在 `ask()` 中把计数器放进 graph state

#### C7 ｜ 依赖未锁版本（P2）
- **位置**：`requirements.txt`（`openai`、`chromadb`、`fastapi` 等无版本约束；其余为宽松区间）
- **现象**：当前环境 `openai 2.54.0`、`langchain 0.3.30`、`langgraph 1.0.1`、`chromadb 1.5.9`、`fastapi 0.115.9`，`pip check` 无冲突

- **建议**：`pip freeze > requirements.lock.txt` 并固定关键包（chromadb/langgraph/openai/fastapi）；`requirements.txt` 保留区间供首次安装

#### C8 ｜ 无鉴权、CORS `*`、默认监听 0.0.0.0（P3）
