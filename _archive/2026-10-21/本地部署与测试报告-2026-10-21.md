1. **可正常部署**：复用既有 `node_modules` / `.venv` / `db_md`，零代码改动拉起 11434 / 3098 / 14052 三端，健康检查全部通过，`pip check` 无冲突、`npm ls` 无缺包。

## 五、问题清单与修复建议

### P1 —— 影响功能可信度或整合方案

| # | 问题 | 证据 | 修复建议 |
|---|---|---|---|
| Q1 | **附件只展示不上传**：文件仅生成 UI 卡片，内容从未进 prompt；仅发附件时 LLM 分支 → 上游 400 → 500，RAG 分支报“问题不能为空” | E1 + 代码走查 | 二选一：① 收敛——隐藏附件/图片入口并标注“暂不支持”（1h，推荐先做）；② 实现——`FileReader.readAsText` 截断 8k 拼入 user message，并在 `handleSend` 前置校验 |
| Q2 | **网关丢弃 `response_format`/`tools`/`tool_choice`/`stop`/`seed`**：A3 的结构化输出链无法经 A1 出网 | 契约测试 0/5 | `handleOpenAIChatCompletions` 解构补 5 字段 → 透传进 `options` → `buildOpenAIChatBody` 原样写入 body；约 15 行，补一条契约用例防回归 |
| Q3 | **缺 `/v1/embeddings`**：向量化无法收敛，A3 必须自持第二把 Key | E2 | 新增 `POST /v1/embeddings`：复用 `getProviderFetchConfig` 转发 `${baseURL}/embeddings`，透传 `model/input/encoding_format`；约 25 行 |

### P2 —— 健壮性与体验

| # | 问题 | 证据 | 修复建议 |
|---|---|---|---|
| Q4 | **错误码语义错误**：上游 4xx 一律 500；非法 JSON 也 500 | E1/E4 | 抛错时携带 `status`（`err.status = upstream.status`），catch 用 `error.status ?? 500`；`getBody` 解析失败返回 400 |
| Q5 | **纯空白问题触发 4 轮检索**：159s、8~12 次模型调用 | 空白用例 | `/chat` 入口 `if not req.question.strip(): raise HTTPException(400, ...)`；`Field(max_length=2000)` |
| Q6 | **RAG 模式搜索弹窗必 404**：`SearchDialog` 走 `createChatCompletion`，被拼成 `:14052/v1/chat/completions` | E8 | RAG 模式下禁用该入口，或改为调用 `createRagChat` 并渲染 sources |
| Q7 | **前端直接展示英文 `Failed to fetch`，且所有 fetch 无超时/取消** | X1/X2 | 封装 `fetchWithTimeout`（对话 60s / RAG 180s + AbortController）；`TypeError` 映射为“无法连接模型网关/知识服务，请确认服务已启动” |
| Q8 | **流式重复 `finish_reason:"stop"` 帧** | T7 `finish_frames=2` | 循环内记 `finishForwarded`，收尾只在未发送时补帧 |
| Q9 | **hy3 `max_tokens` 过小导致正文为空** | `content_len=0` | 已在 UI 默认 4096 规避；建议服务端对 hy3 设下限（如 1024）或返回 warning 字段，文档同步 |
| Q10 | **启动健壮性**：阈值无默认值、`.env.example` 指国际站、Key 校验在 import 期执行 | 代码走查 | `int(os.getenv("REGENERATION_THRESHOLD", "5"))`；示例改中国站；`validate_llm_api_key` 移到 `get_graph()` 内 |
| Q11 | **状态与并发**：`_sessions` 无 TTL；熔断计数为单实例共享；Pydantic 序列化告警刷屏 | 服务日志 | 会话加 LRU/TTL；计数器放进 graph state；Pydantic 告警可忽略或升级序列化配置 |
