#### A0 ｜ 建立 git 基线【必做】【最先做】

- **问题描述**：项目无版本库，此前已发生过"永久删除不可恢复"事件（本环境删除不进回收站）。
- **影响范围**：全项目。
- **修复目标**：一次干净基线提交，后续任何改动可 `git diff` / `git checkout` 回滚。
- **涉及文件**：项目根（新建 `.gitignore`、`.git/`）。
- **操作**：
  ```bash
  git init
  cat > .gitignore <<'EOF'
  node_modules/
  .venv/
  db_md/
  dist/
  .env
  .env.*
  !.env.example
  *.log
  _archive/backup-*/
  EOF
  git add -A && git commit -m "baseline: 整改前基线"
  ```
- **验收标准**：`git log --oneline` 有一条基线；`git status` 干净；`.env`、`node_modules`、`db_md` 未被追踪。
- **风险**：`.gitignore` 写错导致 `.env` 被提交——**提交前必须 `git status` 目视确认无 `.env`**。

## 第二部分 · 功能修复（F 组：完整性审计缺陷）

> 全部修复建议先在新开分支上做：`git checkout -b fix/integrity-audit`。每组修复给出可独立执行的改动与验证。

### F1 ｜ 网关透传 `response_format` / `tools` / `tool_choice`【必做，P1】

- **当前缺陷表现**：`POST /v1/chat/completions` 请求体中的 `response_format`、`tools`、`tool_choice` 被静默丢弃；下游 LangChain 的 `with_structured_output(json_schema)` 若经本网关调用，模型输出不受约束，解析大概率失败。对应审计 A2。
- **根因分析**：`src/index.js` 的请求解构（约 L513）只取 7 个字段；`buildOpenAIChatBody`（L238）组包时不带这三个字段。
- **修复思路**：解构补 3 字段 → 放入 options → 组包时透传（仅混元/DeepSeek 原生 fetch 分支必做；AI SDK 分支可后续）。
- **代码改动点**：
  ```js
  // ① handleOpenAIChatCompletions（约 L513），解构行改为：
  const { model, messages = [], stream = false, temperature, top_p, max_tokens,
          stream_options, response_format, tools, tool_choice } = body;

  // ② options 组装处（约 L522）追加：
  if (response_format && typeof response_format === 'object') options.response_format = response_format;
  ```

### 4.2 兼容性要求

1. **端口不变**：11434 / 3098 / 14052，任何一处改动都会连锁影响前端默认值与测试脚本。
2. **契约字段不动**：`{question, session_id}` → `{session_id, answer, sources, steps}`、五个图节点名、`STEP_LABELS` 键、localStorage 键（`llm-setting-storage`、`llm-chat-storage`）。
3. **运行时约束**：
   - services/knowledge-rag 的 chromadb 依赖 venv 内 MSVC DLL 补丁，**重建 `.venv` 必须重做**；
   - `REBUILD_VECTORSTORE` 建库完成后立刻改回 `False`；
   - TokenHub Key 属中国站，所有基址必须是 `tokenhub.tencentmaas.com`。
4. **编码约束**：所有含中文的文件以 UTF-8 读写；Git Bash 的 `curl -d` 不传中文。
5. **性能预期**：RAG 单问 50~95s 属正常；hy3 为思考型模型，`max_tokens` 不可过小（<4096 可能出现 `content` 为空）。

### 4.3 回滚方案

| 场景            | 回滚动作                                                                    |
| ------------- | ----------------------------------------------------------------------- |
| 单项修复出问题       | `git checkout -- <文件>` 回到基线；或 `git diff` 反向应用                           |
| 阶段 5/6 整批出问题  | `git reset --hard <基线提交哈希>`，恢复 `_archive/backup-当日/` 的 `.env` 与 `db_md` |
| 向量库重建失败       | 恢复备份的 `db_md/`，`REBUILD_VECTORSTORE=False` 启动即可用旧库                      |
| 目录重命名后跑不起来    | `git reset --hard` 回基线 → 先只改引用不改目录，分批缩小范围                               |
| 环境被破坏（venv 崩） | 用 `requirements.lock.txt`（F11 产物）重建 venv + 重做 DLL 补丁 + 恢复 `db_md` 备份    |
